# HAMZA AGENCY — Project Checkpoint Reference

هذا الملف مرجع رسمي داخل GitHub لحالة مشروع HAMZA AGENCY.
الغرض منه منع تكرار تنفيذ نفس الخطوات في هذه المحادثة أو أي محادثة لاحقة.

## قاعدة العمل المعتمدة

قبل اقتراح أو تنفيذ أي خطوة جديدة، يجب مراجعة هذا الملف والتأكد أن الخطوة ليست ضمن المنجزات المعتمدة.
أي بند ضمن قائمة المنجزات يعتبر مغلقاً ولا يعاد تنفيذه إلا بطلب صريح من صاحب المشروع.

---

## تعريف الحالة الرسمية الحالية

1. **نسخة الإطلاق الأولى**
   - المشروع من ناحية الكود والتجربة الأساسية جاهز تقريباً.
   - المنجزات الموجودة في هذا الملف لا تعاد ولا تفتح من جديد إلا بطلب صريح.
   - المتبقي للإطلاق الأول هو المؤجلات الرسمية والفحص النهائي فقط.

2. **إنهاء المشروع الكامل**
   - بعد مراجعة المحادثات القديمة، قرر صاحب المشروع أن الإغلاق الكامل لا يقتصر على نسخة الإطلاق الأولى.
   - الإغلاق الكامل يشمل متطلبات توسعية وإدارية وتجارية إضافية موثقة في قسم مستقل أدناه.
   - أي بند توسعي لا يعتبر منجزاً بمجرد وجود صفحة أو أساس جزئي، بل يحتاج تنفيذ كامل أو قرار تأجيل صريح.

---

## المؤجلات الرسمية للإطلاق الأول

1. إنشاء بريد رسمي للدومين.
   - مؤجل بطلب صاحب المشروع.
   - أمثلة: info@hamza-agency.com أو support@hamza-agency.com.
   - يتم من مزود الدومين أو خدمة بريد خارج الكود.

2. الفحص البصري النهائي من جهاز صاحب المشروع بعد آخر نشر ناجح على Vercel.
   - الصفحة الرئيسية، البرامج، تفاصيل البرامج، الانضمام، طلب الخدمة، التتبع، الوظائف، الفوتر، الجوال، سطح المكتب، لوحة الإدارة، النسخة الاحتياطية.
   - المتبقي هنا ليس كوداً جديداً، بل تأكيد بصري/يدوي من المتصفح بعد النشر.

3. مراقبة Google Search Console بعد الفهرسة.
   - sitemap نجح واكتشف الصفحات.
   - المطلوب لاحقاً مراقبة الفهرسة فقط من حساب Google Search Console.

4. إضافة روابط السوشيال الرسمية عند توفرها.
   - لا يتم إضافة روابط غير رسمية أو تجريبية.
   - لم يتم اعتماد أي روابط سوشيال حتى الآن لأن صاحب المشروع لم يزوّد روابط رسمية مؤكدة.

1. حسم قرار زر قائمة الموقع العامة PublicQuickNav:

2. توثيق الحالة النهائية للدعم الذكي بعد تفعيله إنتاجياً:
   - الموجود حالياً أساس عام وإداري.

3. توثيق أي قرار بتأجيل توسعة من التوسعات أدناه حتى لا تُعامل كمنسية.

## متطلبات إنهاء المشروع الكامل — توسعات معتمدة

### 1. White Label / نسخة قابلة للبيع لوكالات أخرى

1. فصل هوية HAMZA AGENCY عن الكود قدر الإمكان.
2. جعل اسم الوكالة، الشعار، الألوان، الواتساب، البريد، الدومين، وروابط السوشيال قابلة للتعديل من لوحة الإدارة.
3. تحويل النصوص الثابتة الخاصة بحمزة إلى إعدادات أو محتوى قابل للإدارة.
4. تجهيز إعدادات وكالة عامة تشمل الاسم، الوصف، الدولة، العملة، اللغة الافتراضية، وبيانات التواصل.
5. تجهيز Demo / Template نظيف قابل للبيع بدون بيانات حمزة الخاصة.
6. توثيق طريقة تركيب نسخة جديدة لوكالة أخرى.

### 2. الترجمة الكاملة متعددة اللغات

1. تحويل نظام اللغة من واجهة فقط إلى ترجمة حقيقية كاملة.
2. دعم العربية والإنجليزية والتركية للموقع العام والمحتوى الأساسي.
3. دعم SEO منفصل لكل لغة.
4. اعتماد مسارات أو بنية لغات واضحة مثل /ar و /en و /tr أو بديل تقني معتمد.
5. منع كسر المحتوى العربي الحالي أثناء التوسعة.

### 3. الترجمة التلقائية من العربية

1. عند تعديل أي نص عربي من لوحة الإدارة، يتم توليد ترجمة إنجليزية وتركية.
2. تطبيق ذلك على الصفحات، البرامج، الخدمات، الإعلانات، FAQ، مركز المعرفة، التقييمات، وقصص النجاح.
3. دعم مراجعة الترجمة قبل النشر أو اعتمادها حسب إعداد واضح.
4. حماية الترجمة اليدوية من الاستبدال التلقائي غير المقصود.

### 4. تفعيل الدعم الذكي إنتاجياً

1. تثبيت الدعم الذكي كميزة رسمية كاملة للزوار.
2. ربطه بقاعدة المعرفة بشكل واضح.
3. تمكين الإدارة من إضافة وتعديل وحذف أسئلة وأجوبة قاعدة المعرفة.
4. حفظ الأسئلة غير المجابة والمحادثات.
5. عرض تنبيهات للإدارة عند وجود أسئلة جديدة غير مجابة.
6. جعل الدعم يجيب فقط من معلومات الوكالة، مع تحويل واضح إلى واتساب عند عدم وجود جواب.
7. ربط صفحة الخدمات الرقمية بالدعم الذكي.
8. اختبار الدعم الذكي على الجوال وسطح المكتب.

### 5. SEO المتقدم

1. Metadata منفصلة لكل صفحة عامة مهمة.
2. SEO تفصيلي لكل لغة بعد تنفيذ الترجمة الكاملة.
3. تقوية محتوى الصفحات العامة وصفحات البرامج.
4. إضافة Structured Data متقدم مثل Organization وFAQPage وBreadcrumb وService وJobPosting.
5. تحسين SEO صفحة الشركاء والصفحات القانونية والخدمات الرقمية.
6. المنفذ حالياً من Structured Data: FAQPage لصفحة /faq، وService + BreadcrumbList لصفحة /services.

### 6. نظام تتبع طلبات الانضمام بكود خاص

1. تحويل تتبع طلب الانضمام من البحث بالواتساب والبرنامج إلى كود طلب خاص.
2. توليد كود لكل طلب انضمام مثل HA-YYYY-######.
3. عرض الكود بعد إرسال الطلب وحفظه في قاعدة البيانات.
4. تعديل صفحة التتبع للبحث بالكود.
5. إبقاء رقم الواتساب مخفياً عند عرض النتيجة.
6. تعديل لوحة الإدارة لعرض ونسخ كود الطلب.

### 7. Activity Log الكامل

1. تصحيح صلاحية صفحة Activity Logs لاستخدام activity_logs بدلاً من dashboard. — منفذ.
2. تسجيل كل عمليات الإدارة المهمة: إضافة، تعديل، حذف، إخفاء، إظهار، قبول، رفض، تغيير حالة، تصدير، وإنشاء نسخة احتياطية. — منفذ جزئياً على أغلب الصفحات الأساسية.
3. تسجيل المستخدم، الوقت، القسم المتأثر، ومعرّف السجل. — منفذ حسب الصفحات المربوطة.
4. تسجيل القيم القديمة والجديدة عند الإمكان. — منفذ جزئياً حسب الصفحة.
5. إضافة فلترة وبحث متقدم. — موجود أساسياً ويحتاج توسعة لاحقة إن لزم.
6. المتبقي الوحيد المؤجل في المرحلة الأساسية: app/admin/page.tsx داخل updateStatus و saveInternalNotes.

### 8. Trash System الكامل

1. التأكد أن كل حذف من الإدارة يذهب إلى السلة قبل الحذف النهائي.
2. دعم الاسترجاع لكل الأقسام الأساسية.
3. تسجيل الحذف والاسترجاع في Activity Log.
4. جعل الحذف النهائي متاحاً للمشرف الأعلى فقط.

### 9. Backup System الكامل

1. توسيع النسخ اليدوي الموجود إلى تصدير أشمل.
2. دعم JSON وCSV/Excel عند الحاجة.
3. تسجيل كل نسخة احتياطية في Activity Log مع من أنشأها، وقتها، حجمها، والجداول المشمولة.
4. دراسة النسخ التلقائي أو المجدول لاحقاً إذا قرر صاحب المشروع.

### 10. Export Center الكامل

1. تحويل مركز التصدير من واجهة روابط إلى نظام تصدير فعلي شامل.
2. دعم CSV وExcel وJSON.
3. تطبيق التصدير على طلبات الانضمام، طلبات الخدمات، الوظائف، طلبات الوظائف، البرامج، الصفحات، التقييمات، الشركاء، وActivity Logs.
4. إضافة فلاتر قبل التصدير.
5. تسجيل عمليات التصدير.

### 11. Permissions / Roles المتقدمة

1. تقوية نظام الصلاحيات الحالي.
2. ضبط Program Admin ليشاهد برنامجه فقط.
3. اختبار أدوار super_admin وdeputy_super_admin وprogram_admin.
4. توثيق الصلاحيات داخل الإدارة.

### 12. Knowledge Base الكامل

1. تحويل صفحة قاعدة المعرفة إلى إدارة كاملة.
2. دعم إضافة، تعديل، حذف أو تعطيل الأسئلة والأجوبة.
3. تصنيف الأسئلة.
4. ربطها بالدعم الذكي.
5. دعم اللغات بعد تنفيذ الترجمة.
6. تسجيل التعديلات في Activity Log.

### 13. Page Builder / Sections الكامل

1. ربط أقسام الصفحات فعلياً بكل الصفحات العامة.
2. دعم إضافة وترتيب وإخفاء وتعديل وحذف الأقسام.
3. دعم أنواع أقسام مثل Hero وCards وFAQ وStats وGallery وCTA وText block.
4. دعم الترجمة للأقسام.
5. دعم الصور من Media Library.
6. منع كسر التصميم العام.

### 14. Media Library المتقدمة

1. ربط كل الصور العامة من Media Library حيث يلزم.
2. دعم استبدال الصور والحذف الآمن.
3. إخفاء أسماء الملفات من الواجهة العامة.
4. دعم alt text للـ SEO.
5. ربط الصور بالصفحات أو البرامج.
6. دعم اختيار صورة OG لكل صفحة.

### 15. التحكم بالخلفيات والتجربة البصرية من الإدارة

1. ربط اختيار الخلفية من لوحة التحكم.
2. توفير عدة خلفيات جاهزة.
3. حفظ خلفية عامة للموقع وخلفية خاصة لكل صفحة أو برنامج عند الحاجة.
4. دعم خيار خفيف للجوال.
5. منع الوميض وتوثيق المؤثرات الثقيلة المعطلة على الجوال.

### 16. الإحصائيات والمحتوى من Settings CMS

1. نقل أرقام الهيرو والإحصائيات إلى لوحة الإدارة.
2. جعل عدد صناع المحتوى، عدد الفرص الشهرية، عدد المنصات، وعبارات الثقة قابلة للتعديل بدون كود.
3. دعم ترجمتها لاحقاً.
4. ربطها بالصفحة الرئيسية.

### 17. Public Text Audit

1. فحص كل النصوص الظاهرة للزوار.
2. إزالة أي كلام داخلي أو تقني.
3. إزالة أي ادعاءات قوية أو غير مثبتة.
4. توحيد أسلوب الكتابة.
5. مراجعة الصفحة الرئيسية، البرامج، الخدمات، طلب الخدمة، التتبع، الوظائف، FAQ، والسياسات.

### 18. Visual / Responsive Final QA

1. فحص موبايل، لابتوب، شاشة كمبيوتر كبيرة، وتابلت عند الإمكان.
2. فحص الهيدر، الهيرو، الأزرار العائمة، زر اللغة، الدعم الذكي، واتساب، والـ horizontal scroll.
3. فحص الوميض والأداء العام.
4. حسم قرار زر قائمة الموقع.

### 19. البريد واستعادة كلمة المرور

1. إنشاء بريد رسمي للدومين.
2. ربط البريد بالنماذج أو الإشعارات لاحقاً عند الحاجة.
3. تفعيل استعادة كلمة المرور من صفحة دخول الإدارة. — منفذ.
4. ضبط Supabase redirect URLs.
5. اختبار reset password من الموقع نفسه.

### 20. Notification Center الكامل

1. ربط الإشعارات بالأحداث الفعلية.
2. إشعار عند طلب انضمام جديد، طلب خدمة جديد، سؤال AI غير مجاب، أو نشاط مهم.
3. دعم مقروء/غير مقروء.
4. تسجيل الإشعارات داخل الإدارة.

### 21. Analytics / KPI Dashboard المتقدم

1. عرض معدل القبول والرفض.
2. عرض وقت مراجعة الطلب.
3. عرض أكثر البرامج طلباً وأكثر الدول.
4. عرض طلبات الخدمات حسب النوع.
5. عرض أداء الوظائف ونشاط الإدارة وأسئلة AI الأكثر تكراراً.
6. دعم تصدير التقارير.

### 22. التوثيق والتسليم

1. دليل تشغيل المشروع.
2. دليل لوحة الإدارة.
3. دليل إنشاء وكالة جديدة.
4. دليل ربط Supabase وVercel والدومين.
5. دليل البريد الرسمي وSearch Console.
6. دليل الترجمة والدعم الذكي والنسخ الاحتياطي.
7. Checklist نهائي للتسليم.

## ملخص الحالة النهائية

المشروع من ناحية الكود والتجربة الأساسية جاهز تقريباً لنسخة الإطلاق الأولى.
لا يتم إعادة تنفيذ أي شيء من قائمة المنجزات.
الإغلاق الكامل للمشروع يتطلب تنفيذ التوسعات المعتمدة أعلاه أو تأجيل كل بند منها بقرار واضح من صاحب المشروع.
صفحة FAQ Admin مغلقة من ناحية الكود والنشر وRLS، والمتبقي عليها اختبار عملي مؤجل فقط.
Activity Logs الأساسية مكتملة تقريباً، والمتبقي الوحيد app/admin/page.tsx مؤجل بطلب صاحب المشروع.
